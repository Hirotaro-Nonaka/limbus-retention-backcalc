理由に一部だけ精密な終端日を使い残りは推定に頼るという混在処理はせず、**全5ステージで同一種類の規約
（配信ラベルの暦月）を適用**した。結果として25-10アンカーのマスクは2025年10月のみで、チャートに
実際に描画されている2025年11月上旬分は含まない。

## 3. モデル拡張(強制ログ)

`core.py`の`Fitter`は単一アンカー（jan_mask/dau/mau/ratioが1組）しかサポートしない。本タスクは
最大5アンカー同時投入(ステージ5)を要求するため、`v2/task_c/run_task_c.py`に
`MultiAnchorFitter(core.Fitter)`を実装し、`solve()`/`report()`をアンカーのリストに対してループする
形に一般化した。BOUNDS・カーネル(`R_kernel`/`A_kernel`)・設計行列ビルダー(`build_X`/`build_X_kernel`)・
2段階Powell→Nelder-Mead最適化(`fit()`)は`core.Fitter`からすべてそのまま継承。各アンカーの重み付け規約
（DAU行=相対誤差5%、MAU行=相対誤差3%、比率ペナルティ幅0.02、r0=そのアンカー自身のDAU/MAU比）は
core.pyの単一アンカー規約(26-01のr0=0.455は360639/792250から算出されたもの)をそのまま複製した。
これは実験そのものを実行するために必須の拡張であり(v1にはこの機能がないため代替不可能)、
フィット前に決定済み。

## 9. 懸念点・限界

- ステージ4〜5でc・k・τが同時に3パラメータ境界張り付きとなっており、λ/k/p/c/τの構造分解値は
  この2ステージでは信頼できない(v1の7タイトル一般化検証§3.1と同じ論点)。
- τの下限200日への張り付き(ステージ4〜5)は、BOUNDSで許容される最短の「超コア層寿命」に張り付いた
  ものであり、これより短いτが真値である可能性をこの実験は排除できない(BOUNDS緩和はこのタスクの
  スコープ外、診断のみ)。
- ブートストラップ回数はステージ間で統一してN=100(v1のブロック・ブートストラップ100回と同一)を
  維持したが、ステージ5のみ実行環境の制約で独立シードでの再実行になっている(§0参照)。
