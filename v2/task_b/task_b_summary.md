作業ディレクトリ: `v2/task_b/`。スクリプト: `run_task_b.py`(再実行可能、seed=20260719固定)。

## 0. 定義(凍結、変更なし)

- `r(t) = CCU(t)*24/(h*DAU_official(t)) − 1`。CCU(t)はv1と同じ曜日調整済みSteam CCU系列(`core.py::limbus_setup()`の`adj`、Fitterの`self.y`そのもの)。DAU_officialはSTEAM run1(主系列)。
- `g(t)`はcore.py `Fitter.__init__`が構築する凍結済みイベント窓プロファイル(exp3・単位ピーク・イベント横断maxクリップ、短期イベント窓7日/長期イベント(Launch・Collab)窓14日)を**無変更で流用**(`f.g`をそのまま使用)。
- 回帰は宣言どおり `r(t) ~ a + β·g(t)`(切片あり)。
  - **h=2.2固定**: 切片は理論的にはh=2.2が正しければ0。
  - **h自由推定**: `q(t)=CCU*24/DAU_official = h·(1+β·g(t))` を `q ~ a + b·g` に回帰し、`h_hat=a`、`β_hat=b/a`。hのズレは切片に吸収される。
  - 参考: h=2.128(v1フィット値、タスクaで再現確認済み)固定でも算出。
- 第1区間(2023-08-01〜2024-07-01)は**回帰(識別)に使用禁止**(拘束条件)。記述統計のみ全4区間で報告。

## 2. 識別可能性チェック(区間2〜4のみ)

- STEAM run1、区間2〜4のデジタイズ点: n=387、日付間隔 中央値=1.00日・平均=1.48日(プロトコル事前見積り ~1.45日/pxとほぼ一致)。連続する点で値が同一(同一ピクセル由来の可能性)な行は19.6%(76/387) — 完全独立ではないが、大半の点は異なる値を持つ。
- **イベント窓カバレッジ**: 区間2〜4に該当するイベント31件(LIMBUS_EVENTS+SPIKES)すべてが、窓内(g>0)にデジタイズ点を**2点以上**含む(0点=0件、1点=0件、2点=1件、4点=7件、5点=22件、9点=1件)。事前に懸念していた「解像度不足で分離不能」という事態は**発生しなかった**——実測解像度は事前見積りの下限リスクより良好で、g>0の各イベント窓内で複数点によりCCUブースト形状を追える。
- 回帰用データ: n=387(g>0が149点、g=0が238点)。

**結論**: この解像度でβは**識別可能**(下記の通り95%信頼区間が0を除外)。プロトコル§4に事前開示していた「識別不能なら格下げ」の条件は発動しない。

## 2.5 [TB-1] 残差の系列相関とブロックブートストラップへの補正

初版のiid行リサンプルブートストラップ(下記§3で「補正前・非公表」として残す)は、回帰残差(h=2.2固定、区間2〜4、日付順)の系列相関を無視していた。監査の指摘どおり再計算した診断値:

- lag1自己相関 ρ₁ = **0.7095**
- Durbin-Watson = **0.579**
- n_eff = n(1−ρ)/(1+ρ) = 387×(1−0.7095)/(1+0.7095) ≈ **65.8**(n=387に対し約1/5.9)

**ブロック方式(実行前に宣言、`run_task_b.py`冒頭docstringに記載済み)**:
- **(i) イベント窓ブロック(主報告として宣言)**: マージ済みイベント窓(g>0区間)+その直前の非イベント区間を1ブロックとする(K=28ブロック、区間2〜4)。宣言理由: 系列相関の発生源はイベントパルス過程g(t)自体に構造的に紐づくため、「1イベント周期」を単位とするブロックが実際の依存構造に最も忠実。
- **(ii) 固定長14日カレンダーブロック(副次・ロバスト性確認として宣言)**: 残差の減衰スケール(ρ₁=0.71、平均行間隔1.48日から見積もる減衰ホライズン約7〜10日)の≥1倍として14日を採用(K=41ブロック)。監査指示で例示された長さと一致。
- 両方式ともブロックを復元抽出(5000回)、各反復で従来どおり8.20%独立読み取り誤差ノイズも同時に付加。

**[自己チェック、正直に開示]**: 監査は「iid CIは約2.4倍狭すぎる」との見積りを提示したが、実際にブロックブートストラップを実行したところ、CI幅の拡大は**主方式で約1.13倍(0.202→0.228)、副方式で約1.18倍(0.202→0.238)**に留まり、2.4倍には遠く届かなかった。ブロック長を14日〜60日まで振っても(K=41〜10)CI幅は0.219〜0.253の狭いレンジ内で頭打ちになることを確認した(感度診断、非公表)。**この乖離の考えられる理由**: 監査のn_eff=n(1−ρ)/(1+ρ)という補正係数は、AR(1)型誤差のもとでの**平均**推定量の分散膨張に対する標準的近似であり、本タスクの対象は**g(t)というまばら・局所的な(0付近に多く、イベント時のみ立ち上がる)回帰変数に対する回帰の傾き**である。回帰の傾き推定の分散膨張は、誤差の自己相関だけでなく回帰変数自身の自己相関構造にも依存するため、g(t)のような非平滑・非AR(1)的な変数では、単純な「n/n_eff」則がそのまま傾きの分散膨張率に一致するとは限らない。この点は監査による再検証を推奨する(本レポートでは実測したブロックブートストラップ結果をそのまま公表値として採用し、乖離を隠さず記録する)。

## 4. 読み取り誤差の伝播・バイアス方向(手順どおり+監査指摘[TB-2][TB-3]反映)

STEAM読み取り誤差floor 8.20%を、ブロックブートストラップの各反復で**独立**な乗法的ノイズ(DAU_officialに`N(0, 8.2%)`を乗算)として点ごとに付加し、同時にブロック単位のリサンプリング(§2.5)も行った(5000回)。

**独立ノイズを仮定した理由(保守的選択、明記)**: usage_conditions.mdは「軸較正誤差が共通モード」と明記しており、真の読み取り誤差の一部は全点に共通の水準シフトである可能性が高い。共通モード成分は一次近似で切片(intercept)に主に吸収され、g(t)と相関しない限りβ_hat(傾き)への影響は小さい(r_true ≈ r_obs − δ、δが定数の場合)。それにもかかわらず本分析では8.2%を**全点独立**とみなしてブートストラップに投入した——これは実際の伝播より**広め(保守的)**なβ_hatの不確実性区間を与える選択であり、狭すぎるCIを報告するリスクを避けるための意図的な保守化である。

**[TB-2] 上方バイアスの可能性**: イベント相関の読み取り誤差はrun間で非対称(窓内7.40% vs 窓外6.40%)で、run2のカバレッジも窓内47%・窓外58%と非対称。両runに共通するピーク・クリッピング(公式チャートの描画上の頭打ち等)はrun1-run2差分では検出できないため、真のβはここでの推定値より**上方に偏っている可能性**がある。加えてCCU側は高解像度(日次)・DAU側は低解像度(≈1.45日/px)という解像度の非対称性も、イベント窓の立ち上がりをCCU側で正確に、DAU側で粗く捉えることになり、同方向のバイアス源になりうる。

**[TB-3] 下方バイアスの可能性(逆方向)**: g(t)の境界(イベント窓の開始・終了日)には±1.45日/px相当の日付誤差が残る。これは説明変数の測定誤差(errors-in-variables)にあたり、標準的な結果として回帰係数を0方向に減衰(attenuation)させる——βを**過小推定**させる方向に働く。

**正味のバイアス方向は不確定**(TB-2は上方、TB-3は下方、双方の相対的な大きさを定量化する追加検証はしていない)。したがって本タスクのβ_hatは「符号と大まかな大きさ(0.3を上回る)」については頑健と考えるが、点推定値そのもの(0.44〜0.54)を確定値として過度に精密に扱うべきではない。

## 5. v1 D180統合バンド[3.0%, 6.6%]への含意

v1はβ=0.3を「妥当な上限」と仮定してD180≤6.6%とバンドを設定した。**本タスクの経験的推定 β_hat=0.44〜0.54(監査補正後の主95%CI: 下限0.327〜上限0.682)は、v1が上限と仮定したβ=0.3を明確に超えている**。この表を線形補間する範囲では、β=0.44〜0.54はD180≈7.7%〜9.6%程度に対応する(β=0.3→6.55%、β=0.5→9.79%の間を補間した粗い目安であり、βを固定した状態でのモデル再フィットは本タスクでは実施していない——正確な値には別途モデル再フィットが必要)。

**[TB-4、監査確定の限定表現]**: このD180≈7.7〜9.6%という数値は、(a)本タスクのβ(イベント窓内での瞬間的CCUブースト率)とv1の感度分析のβ(モデル内で外生的に振る同名パラメータ)が単位対応する、という前提と、(b)β固定での正式なモデル再フィット待ちの粗い目安、という**2つの限定を明示した上でのみ**言及可能な数値である。**独立した結果数値として論文本文やレポートの見出し等に単独で流通させてはならない**——必ず上記の限定を併記すること。

**結論(圧縮ではなく拡大方向、監査補正後も維持)**: 事前の期待(「D180バンド3.0〜6.6%の圧縮」)とは逆に、外部データ(公式DAUチャート)から独立に推定したβは、v1が上限とみなしていた値を超えていた。これは手法を事後に変更した結果ではなく、宣言どおりの回帰を実行した結果として得られた事実であり、そのまま報告する。ブロックブートストラップ補正後もβの95%CI下限(0.327〜0.391)はなおv1の仮定上限0.3を上回るか同程度であり、結論の頑健性は保たれる。**D180バンドは圧縮ではなく、上方修正(上限を6.6%超に広げる)を示唆する経験的根拠がある**、という記述にとどめる(β固定での正式なモデル再フィットはPhase 2 task bの範囲外につき未実施)。ただし[TB-2][TB-3]のとおり正味のバイアス方向は不確定であり、点推定の精密な数値(0.44/0.54)そのものより「0.3を上回る」という定性的な方向性を主たる結論として扱う。

## 結論(箇条書き)

- 識別可能性: 事前開示の「識別不能リスク」は**発生しなかった**。区間2〜4の実測解像度(中央値1.0日/点)は、31件全イベント窓に2点以上を捉えるのに十分だった。
- **[監査補正後、公表値]** β_hat(h=2.2固定、主報告)= 0.443、95%CI(主: イベント窓ブロックブートストラップ)[0.327, 0.555]。β_hat(h自由推定、主報告)= 0.541、95%CI [0.391, 0.682]。副方式(固定14日ブロック)でも同様に0を除外([0.330,0.573]/[0.397,0.703])。旧iid行リサンプルCI([0.347,0.549]/[0.419,0.678])は残差の系列相関(ρ₁=0.71、n_eff≈66)を無視しており**非公表・参考値に格下げ**。
- **[自己チェック]** 監査は旧CIが「約2.4倍狭すぎる」と見積もったが、実測ブロックブートストラップでのCI幅拡大は約1.13〜1.18倍に留まった。この乖離は隠さず記録し、監査による再検証を推奨する(§2.5参照)。
- ロバスト性: 区間別個別回帰(0.32/0.55/0.50)・区間固定効果モデル(0.458)いずれも主推定と同オーダーで、r(t)の経年トレンドとの交絡ではない。
- v1のD180統合バンド[3.0%, 6.6%]は、v1が上限として仮定したβ=0.3を経験的推定値のCI下限(0.327〜0.391)でも上回るため、**圧縮ではなく上方拡大の方向を示唆**(監査補正後も結論維持)。ただし正味のバイアス方向は[TB-2](上方)・[TB-3](下方)が拮抗し不確定であり、D180≈7.7〜9.6%という翻訳値は[TB-4]の限定付きでのみ言及可能。
- 読み取り誤差8.2%(floor)は、共通モード成分の影響を過大に見積もる保守的な仮定(全点独立ノイズ)でブロックブートストラップに組み込んだ。CIはこの保守化を含む。

## 懸念点

- CCU⇔DAU比の回帰はcore.pyの固定パルス形状(exp3、3日時定数)を前提としており、パルス形状自体の妥当性は本タスクでは検証していない(凍結設計どおり)。
- 区間2〜4のデジタイズ点の約19.6%は連続する値が同一(ピクセル解像度限界に起因する可能性)であり、真の独立サンプルサイズはn=387よりやや小さい可能性がある。ブロックブートストラップの復元抽出はこの点を部分的に緩和するが、完全ではない。
- D180への翻訳は v1既存表の線形補間であり、β固定での正式な再フィットではない(数値は目安、[TB-4]の限定付き)。
- h自由推定でh_hat=1.800はv1フィット値(2.128)ともプロトコル宣言値(2.2)とも異なる——これはCCU/DAU比が区間2〜4平均でもなお時間トレンドを持つこと(§1のトレンド記述)の影響を受けた1つの集計値であり、真の「定数h」の点推定として過度に重視すべきではない。
- **監査の「iid CIは2.4倍狭すぎる」という見積りと、実測ブロックブートストラップの拡大率(約1.13〜1.18倍)が一致しない**。ブロック長を14〜60日まで振っても拡大率はほぼ横ばい(0.219〜0.253)だった。この不一致の原因(n_eff/nヒューリスティックが平均推定量向けであり、まばらな回帰変数g(t)に対する傾き推定への適用が過大評価である可能性)を§2.5に記録したが、監査側での独立検証を要すると考える。[TB-2][TB-3]と合わせ、β_hatの点推定・CI幅とも「大まかな大きさの把握」以上の精度を主張しない。
