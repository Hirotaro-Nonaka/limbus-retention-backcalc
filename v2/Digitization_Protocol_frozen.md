# v2 デジタイズ・プロトコル(凍結版 v1.0、2026-07-19)

**凍結宣言**: 本手順は、チャートからの数値抽出を開始する**前**に確定した。以後の変更は「事後の手法選択」と「データ制約による強制」を区別して本ファイル末尾の変更ログに記録する(v1論文 §3.4と同じ規律)。抽出値を見てから手順・評価基準を変えることを禁止する。

## 0. 目的

公式配信チャート(docs/*.png、出典: docs/Limbus_Livestreamingdates.md の5配信)から公式のプラットフォーム別DAU/MAU時系列を抽出し、以下に用いる:

- **(a) 軌跡検証**: v1モデルのDAU軌跡と公式DAU曲線の全期間比較(v1は末端1点のみだった)
- **(b) βの経験的識別**: r(t) = CCU(t)·24/(h·DAU_official(t)) − 1 のイベント窓応答からプレイ時間ブーストβを推定し、v1のD180統合バンド3.0〜6.6%の圧縮を試みる
- **(c) アンカー限界価値実験**: アンカー点を1→2→3→4→5点と増やした再フィット系列で、開示1点あたりの識別性の増分を定量化する

## 1. 素材

- 一次素材: `docs/24-10-DAU.png` 〜 `docs/26-01-MAU.png`(10枚)。優先は3周年配信(2026-02-27)の2枚 — DAUは2023-08〜2026-01、MAUは(軸補正後)2024-01〜2026-01をカバーする
- 高解像度が必要な場合、出典YouTube動画から該当フレームを再取得してよい(動画URL・タイムスタンプ・取得方法を記録すること)。**新しい配信・新しい画像素材の追加は変更ログ記載の上でのみ可**

## 2. 抽出手順(凍結)

1. **軸較正**: 各画像でX軸・Y軸の基準点を最低3点ずつ(グリッド線・軸ラベルを使用)取得し、ピクセル→(日付, 人数)のアフィン変換を推定する。較正点の座標は記録する
2. **対象系列**: Steam(赤)を主対象。Total(黄)・AOS(クリーム)・iOS(茶)は可能な範囲で(色分離で自動抽出できる場合のみ)
3. **トレース方式**: 系列色のピクセル列を縦方向に走査し、各X座標での系列中心(色一致ピクセルの中央値)を取る。実効解像度(px/日)を必ず記録する。日次分解能が得られない場合は得られた解像度のまま報告し、**補間で日次を偽装しない**
4. **二重化**: 同一チャートに対し独立に2回抽出(別ツールまたは別日の再実行)し、両者の差分RMSEを**読み取り誤差**として記録・伝播する
5. **26-01 MAUの軸ズレ補正**: X軸ラベルを+6ヶ月シフトして解釈(表記25-07=実26-01。発表者ミス、docs/Limbus_Livestreamingdates.md記載)。この補正は他チャートとの重なり区間の整合で検証する
6. **配信間クロスチェック**: 重なり期間(例: 25-10版と26-01版)で系列を突き合わせ、差分を読み取り誤差の独立推定として記録する。系統的な不一致(公式側の遡及修正の可能性)が出た場合は結果に明記する
7. **出力形式**: CSV列 = date, platform, metric(DAU/MAU), value, source_image, extraction_run(1/2), px_per_day。保存先 `v2/digitized/`

## 3. 事前に宣言する評価方法(HARKing対策)

- **(a) 軌跡検証**: 公式DAU系列とv1モデルDAUの相対RMSE(v1と同定義)を記述的に報告する。合否閾値は事前に設けないが、参照点としてv1ホールドアウトのDAU誤差−5.4%を併記する
- **(b) β推定**: r(t)をイベント窓プロファイルg(t)(core.pyの定義)に回帰。hの扱いは「2.2固定」と「自由推定」の両方を報告する。イベント日サンプルが実効解像度不足で分離できない場合は「この解像度ではβは識別できない」を結論として受け入れる(できるまで手順をいじらない)
- **(c) 限界価値実験**: アンカーの追加順序は**時系列順(古→新)に固定**(24-10 → 25-01 → 25-05 → 25-10 → 26-01)。各段階で報告する量を事前列挙する: 境界張り付きパラメータの数、D180のブートストラップCI幅、τの下限、base/stockの状態。v1の境界緩和診断(§3.5(c))を各段階に適用する
- 監査: 各フェーズの数値成果物は 独立した監査を経てから採用する(v1と同じ)

## 4. 既知のリスク(事前開示)

- スクリーンショット解像度(実効 ~0.8px/日)では日次分解能が出ない可能性が高い。その場合(b)は「週次解像度でのβ上限」等に目標を格下げし、その旨を明記する
- チャートは配信画面のスクリーンショットであり、描画時のアンチエイリアス・重なり(黄と赤の交差)で系列分離が乱れる区間が生じうる。分離不能区間は欠測として扱う(補間しない)
- 公式チャート自体の作図誤差・遡及修正は検証不能。「公式開示値の忠実な読み取り」以上を主張しない
